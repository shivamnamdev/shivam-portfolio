# Phase 2: Content API (curriculum) — Blueprint

Status: **approved by the owner on 2026-11-04** (recommended option on all five decisions in section 9). Correction made while building: the curriculum is keyed by the **cohort** slug (the slug learners enrol in and that progress rows use), not the course slug. Branch `admin-portal/p2-content-api` off `epic/admin-portal`. Part of [admin-portal-plan.md](admin-portal-plan.md) section 7.

## 1. North Star
An admin can build and change a course's curriculum (modules, lessons, assignments, resources) through the API, edit safely as a draft, publish when ready and discard a draft. Learners see nothing different until phase 5.

## 2. Integrations and source of truth
- Supabase only. **No new table and no new SQL**: one `content_docs` row per course, `kind = 'curriculum'` (already allowed by the table's check), `key = cohort slug` (the enrolment slug, for example `python-beginners-batch-2`).
- Today's source: `data/learning-content.ts` (`courseCurriculumMap`, 3 courses, 16 modules). It stays the live source until phase 5.
- Delivery: JSON over `/api/admin/v1/curriculum/**`, same envelope, guard, audit, rate limit and OpenAPI as phase 1.

## 3. Data shapes

```ts
type Resource = { title: string; url: string; type: 'PDF' | 'Document' | 'Link' };
type Assignment = {                       // maps today's githubAssignments entry
  title: string;
  labType?: 'python' | 'git';             // default python
  rawUrl?: string; solutionUrl?: string; starterCodeUrl?: string;                       // python
  instructionsUrl?: string; starterRepoUrl?: string; expectedStateUrl?: string; validatorUrl?: string;   // git lab
  expectedOutcomeUrl?: string;
  carryOverCode?: boolean;                     // today's flag: the lab starts from the previous lesson's code
  isExam?: boolean; serverGraded?: boolean; expectedOutcomeUrl?: string;   // read-only through the API (section 5, R6)
};
type Lesson = { id: string;               // YouTube id (11 chars) or 'doc-...' ; stable, learner progress points at it
                kind: 'video' | 'document'; title?: string; description?: string;
                assignment?: Assignment; resources?: Resource[] };
type Module = { id: string; title: string; advanced: boolean; lessons: Lesson[] };   // order = array order
type CurriculumDoc = { modules: Module[];                 // working copy (draft)
                       published: Module[] | null;        // what learners will see after phase 5
                       publishedAt?: string };
```
Module `id` is generated by the API (`m-` plus 8 random characters) and never reused. Reorder = send the full ordered list of ids, applied in one statement.

## 4. Endpoints (all `/api/admin/v1`, permissions `curriculum:read` / `curriculum:write`, owner has both, staff key read-only)

| Call | What |
|---|---|
| `GET /curriculum` | courses that have a curriculum: counts, `hasUnpublishedChanges` |
| `GET /curriculum/{cohort}` | working copy + published state + version |
| `PUT /curriculum/{cohort}` | replace the whole working copy (`If-Match`); used by import/export, atomic |
| `POST /curriculum/{cohort}/modules` · `PATCH`/`DELETE …/modules/{id}` · `POST …/modules/reorder` | module CRUD, atomic reorder |
| `POST …/modules/{id}/lessons` · `PATCH`/`DELETE …/lessons/{lessonId}` · `POST …/lessons/reorder` | lesson CRUD; reorder can move lessons between modules |
| `POST /curriculum/{cohort}/publish` | copy working copy to `published` |
| `POST /curriculum/{cohort}/discard` | reset working copy to `published` (revert the draft) |

All writes need `If-Match`, are audited with a **summary** (counts, version, ids touched) rather than the whole document, and go through the write rate limit.

## 5. Rules (the part that must be right)
- R1 Lesson ids unique per course; video id matches `^[A-Za-z0-9_-]{11}$`, document id matches `^doc-[A-Za-z0-9_-]{1,60}$`.
- R2 URLs: `https` only, and only the hosts the learner site already allows: `raw.githubusercontent.com`, `s3.ap-south-1.amazonaws.com`, plus `https` YouTube/Drive links for resources of type `Link`. Anything else is refused (400).
- R3 Limits: 60 modules, 200 lessons per module, 20 resources per lesson, text lengths as phase 1.
- R4 A lesson that has learner progress (`video_progress` or `assignment_progress`) **cannot be deleted or have its id changed** (422), because the learner's progress would be orphaned. It can be moved or renamed.
- R5 A published curriculum cannot be emptied (0 modules) (422).
- R6 `isExam` and `serverGraded` cannot be set through the generic lesson endpoints; an import keeps what is already there. Exam graders stay in `lib/examGraders.ts` (reviewed in git, runs on the server). **Amended 2026-11-14 (owner request, proposed in `exam-switch.md`, pending approval):** the flags can be changed only through the dedicated `PUT /curriculum/{cohort}/exam`, and only for a course that already has a grader in code.
- R7 The cohort must exist as a `cohort` row; an unknown cohort is 404. The first write to a cohort without a curriculum creates an empty one (no `If-Match` needed that once).
- R8 Reorder lists must contain exactly the current ids (no missing, no extra, no duplicates), otherwise 400 and nothing changes.

## 6. Adapters (pure, unit-tested, used by the import script next)
- `fromLegacy(courseCurriculumMap[course]) → Module[]`
- `toLegacy(Module[]) → legacy shape`
- Round-trip exit criterion: `toLegacy(fromLegacy(x))` equals `x` after normalisation. Known junk in the data is **reported and dropped** (for example the assignment under the empty key `""` in `python-beginners-batch-2`, the placeholder `rawUrl: "..."` on `Q8vLb-kmFYs`), listed in the import output.

## 7. Tests (written with the code, constitution section 7)
- Unit (no DB): adapters round trip on the 3 real courses, every rule R1-R8 including boundaries, reorder logic, publish/discard transitions, summary audit, permission table.
- API (QA): 401/403/400/404/409/422/428/200 for each endpoint, reorder atomic, publish/discard, R4 with real progress rows, audit rows without the document body.
- OpenAPI contract test extended; new PRD `docs/testing/prd/18-content-api.md` and cases CSV.

## 8. Do not
No learner-facing change, no new table, no new package, no HTML in text fields (plain text, escaped on render later), no code upload.

## 9. Decisions needed from the owner
1. **Draft model:** working copy and `published` inside the same row (no SQL needed). Alternative: a second row kind, which needs a SQL change and gives nothing extra. Recommended: same row.
2. **R4:** refuse deleting a lesson that learners have progress on. Alternative: allow it and orphan the progress. Recommended: refuse.
3. **R2:** host allow-list as above. Alternative: any `https` host (the learner site's CSP would still block unknown hosts).
4. **Junk in today's data:** report and drop it on import (recommended), or keep it as is.
5. **R6:** exam flags read-only through the API (recommended).
